# astro-boilerplate

Go service scaffold for new astronautsid backend services. Combines Clean Architecture's layered code layout with DDD's rich domain modeling. gRPC-first; ships with Postgres read/write split, optional Redis, optional Mongo, optional GCP Pub/Sub, and Datadog APM wired by default.

## Quick start

```bash
# 1. Install Go 1.26
# 2. Copy config template
cp config.yml.example config.yaml

# 3. Start infra (Postgres + Redis + Mongo)
make docker-up

# 4. Run migrations
make migration-up

# 5. Generate mocks (one-off; runs whenever ports change)
make mocks

# 6. Run the service
make run

# 7. (Optional) verify gRPC reflection works
grpcurl -plaintext :8000 list
```

Private dependencies (`github.com/astronautsid/astro-proto`, `astro-golibs`) require GitHub auth. Set:

```bash
export GITHUB_TOKEN=...
git config --global url."https://x-access-token:${GITHUB_TOKEN}@github.com/".insteadOf "https://github.com/"
```

## The dependency rule

```
interface ──▶ application ──▶ domain
                  ▲
infrastructure ───┘   (adapters implement ports declared in application)
```

- `internal/domain/` imports nothing from any other `internal/...` package.
- `internal/application/` imports `internal/domain/` and `pkg/...` only.
- `internal/infrastructure/` may import `internal/application/` (to implement co-located ports) and `internal/domain/`.
- `internal/interface/` imports `internal/application/` and `pkg/...`.
- `cmd/grpc/main.go` is the only place where every layer is wired together.

This is enforced by package layout, not tooling. Reviewers reject PRs that introduce inward-pointing imports.

## Composition root contract

The top of `cmd/grpc/main.go` carries a comment block listing the wiring steps. Every service started from this scaffold keeps the order identical so reviewers can focus on what differs per service.

1. `config.Load()` — env vars; fatal on missing mandatory.
2. `logger.InitLogger(cfg.Log.Level)` from `astro-golibs/logger` — JSON output with caller info; level driven by config.
3. `signal.NotifyContext(...)` + `shutdown.NewManager()` — the ctx propagates into every long-lived resource so SIGTERM/SIGINT flows through naturally; the manager owns ordered, per-phase teardown.
4. `tracer.Start(...)`.
5. Postgres master + replica via `persistence.NewMasterDB(...)` and `persistence.NewReplicaDB(...)` (backed by `astro-golibs/safesql` — typed `MasterDB` / `ReplicaDB`, the replica has no write methods so misuse is a compile error).
6. Distributed lock: `cache.NewNoOp()` by default; `cache.NewLock(redisClient)` when `redis.url` is set.
7. Audit log writer: `vendor_audit.NewNoOp()` by default; `vendor_audit.NewRepository(mongoDB)` when `mongo.uri` is set.
8. Repositories `(writeDB, readDB)`.
9. `persistence.NewTransactionManager(writeDB)`.
10. Optional upstream gRPC clients via `external.NewGrpcClientConn(...)`; skipped when the matching `grpc_service.<entry>.addr` is empty.
11. astro-golibs Pub/Sub client + publisher (no-op publisher fallback when `gcp.project_id` is unset) and optional subscriber (skipped when `pubsub.vendor_events_subscription_id` is empty so the binary boots without GCP credentials).
12. Application command/query handlers.
13. Interface (gRPC) handlers. The health handler holds the master + replica DB handles and verifies them with `SELECT 1` on every Check.
14. `grpc_interface.NewServer(...)` with `grpc.enable_reflection` toggle — interceptor chain is Datadog APM (outer) + astro-golibs `grpc/metadata` (inner, extracts X-Request-ID, X-User-ID, x-device, x-app-version, etc. into typed context values).
15. Register ordered shutdown phases (readiness flip + pre-stop sleep → grpc GracefulStop with timeout race → upstream clients → metrics → mongo → redis → postgres master + replica → tracer). See `pkg/shutdown` for the per-phase timeout + `errors.Join` semantics.
16. Wait on `<-ctx.Done()` (signal) or `<-serveErr` (fatal server crash); `stopSignals()` un-registers the signal handler so a second SIGTERM hits OS default (force-exit); run the manager.

A separate goroutine serves `/metrics` for Prometheus on `http.addr`.

## Configuration

The canonical config format is **YAML**. [config.yml.example](config.yml.example) at the repo root is the schema template; copy it to `config.yaml` (also at the repo root) and adjust per environment. Loading is driven by [viper](https://github.com/spf13/viper) — see [internal/config/config.go](internal/config/config.go).

**Search path.** Viper looks for `config.yaml` in the working directory (`.`). The Dockerfile bakes the example into `/app/config.yaml`, which sits next to the binary at runtime.

**Env-var overrides.** Any key can be overridden at runtime by setting an environment variable. The mapping is `section.field` → `SECTION_FIELD` (nested keys join with underscores):

| YAML key | Env var |
| --- | --- |
| `app.name` | `APP_NAME` |
| `postgres.master.dsn` | `POSTGRES_MASTER_DSN` |
| `grpc_service.account.timeout_sec` | `GRPC_SERVICE_ACCOUNT_TIMEOUT_SEC` |
| `pubsub.vendor_events_subscription_id` | `PUBSUB_VENDOR_EVENTS_SUBSCRIPTION_ID` |

### Connection strings come from env vars, not YAML

The credential-bearing connection strings — `postgres.master.dsn`, `postgres.slave.dsn`, `redis.url`, `mongo.uri` — are **injected at runtime by the infra team via environment variables** and stay empty in the committed YAML:

| Connection string | Env var | Mandatory? |
| --- | --- | --- |
| `postgres.master.dsn` | `POSTGRES_MASTER_DSN` | yes (fail-fast) |
| `postgres.slave.dsn` | `POSTGRES_SLAVE_DSN` | yes (fail-fast) |
| `redis.url` | `REDIS_URL` | optional (empty ⇒ NoOp lock) |
| `mongo.uri` | `MONGO_URI` | optional (empty ⇒ NoOp audit writer) |

The service does not reassemble these from host/user/password parts — the full string is the infra team's contract surface. The YAML carries pool tuning (max conns, idle / lifetime timeouts, dial / read / write timeouts) which is the service's responsibility to set per workload. A test (`TestExampleYAML_DoesNotCommitCredentials`) guards against credentials being re-added to the committed YAML.

### Mandatory keys

`app.name`, `http.addr`, `grpc.addr`, `datadog.agent_addr`, both `postgres.{master,slave}.{dsn,max_open,max_idle,idle_timeout_sec,max_lifetime_sec}`, `grpc_service.account.addr`, `gcp.project_id`. Startup fails fast in `Load()` if any is missing from both YAML and env. Every other key is optional with a sensible default; an empty `redis.url`, `mongo.uri`, or `pubsub.vendor_events_subscription_id` activates the corresponding NoOp / "disabled" code path.

## Conventions cheat-sheet

- **Ports co-located with consumers.** Every `internal/application/<usecase>/` declares the interfaces it depends on. The domain never imports infrastructure interfaces.
- **DTOs cross application boundaries, entities do not.** Application handlers accept and return DTOs. `entity.Vendor` never escapes the application layer.
- **Rich domain.** Aggregate state machines live as methods on the entity. Constructors validate. Errors are sentinels + typed wrappers (`*entity.ValidationError`, `entity.ErrInvalidTransition`).
- **Mocks via `go.uber.org/mock`.** No `//go:generate` directives. `make mocks` regenerates everything via `scripts/generate_mocks.sh`. Mocks land in `<pkg>/mocks/` with package name `<pkg>mock`.
- **Postgres read/write split, enforced at the type level.** Repository constructors take `(write safesql.MasterDB, read safesql.ReplicaDB)`. The replica interface has no write methods — calling `ExecContext` or `BeginTxx` through it is a compile error, eliminating that bug class entirely.
- **NoOp fallbacks.** Redis lock, Mongo audit log, and Pub/Sub publisher all ship NoOp adapters. The binary boots without those services when their env vars are unset — useful for local development.
- **One `*grpc.ClientConn` per upstream service.** `external.NewGrpcClientConn` wraps `astro-golibs/grpc/util.NewConnection` (TLS, Datadog tracing, optional retry). Compose multiple logical adapters off a single conn rather than re-dialing per adapter. See `external/boilerplate/client.go` for the reference adapter shape.
- **Test styles.** Handler tests are white-box (`package handler`). Application tests are black-box (`package <usecase>_test`). Use `testify/require`.
- **`Tx` is opaque.** The persistence adapter delegates to `safesql.MasterDB.ExecuteWithTx` under the hood and type-asserts back to `*sqlx.Tx` via `persistence.SqlxTx(tx)`. Application code never imports `sqlx`.

## Example: the Vendor aggregate

The scaffold ships one complete use case demonstrating the full pattern end-to-end.

| Layer | File | What it shows |
| --- | --- | --- |
| Domain entity | `internal/domain/entity/vendor.go` | Constructor validation + Activate/Deactivate/Suspend state machine + `Reconstitute` for repo hydration + `AssignID` |
| Domain VO | `internal/domain/valueobject/vendor_status.go` | Typed enum with `ParseVendorStatus` |
| Domain errors | `internal/domain/entity/errors.go` | Sentinels + `*ValidationError` with `Unwrap` |
| Domain event | `internal/domain/event/event.go` | `DomainEvent` interface + example events (publisher scaffolded; no adapter yet) |
| Application ports | `internal/application/vendors/{repository,transaction,lock,notification,audit,reader,infra}.go` | Co-located ports |
| Command | `internal/application/vendors/create_vendor.go` | Lock + duplicate check + Tx-scoped Save + audit |
| Query | `internal/application/vendors/get_vendor.go` | Repo read + DTO mapping |
| Persistence | `internal/infrastructure/persistence/vendors/{model,repository}.go` | sqlx adapter; read/write split; sqlmock-based tests |
| Mongo audit | `internal/infrastructure/mongodb/vendor_audit/repository.go` | Document-store adapter implementing `vendors.AuditLogWriter`; ships with `NoOp` |
| Upstream client (example) | `internal/infrastructure/external/boilerplate/client.go` | Typed wrapper around `astro-proto/golang/pb/boilerplate.BoilerplateServiceClient`; demonstrates the one-ClientConn → one-typed-wrapper → plain-Go-types adapter pattern. Wired conditionally in `main.go` based on `grpc_service.boilerplate.addr`. |
| Pub/Sub publisher | `internal/infrastructure/messaging/pubsub/vendors/publisher.go` | Per-domain subpackage. Receives `event.VendorCreated`, builds `erppb.Vendor`, runs `proto.Marshal`, publishes to the topic bound at construction. NoOp variant for local dev. New domains add sibling subpackages (`pubsub/orders/`, `pubsub/customers/`). |
| Pub/Sub subscriber | `internal/infrastructure/messaging/pubsub/subscriber.go` | Thin wrapper over astro-golibs `RegisterSubscription` with the boilerplate's default ReceiveSettings preset (NumGoroutines: 4, MaxOutstanding: 10, 1 MiB, 10 min MaxExtension) |
| Pub/Sub inbound handler | `internal/interface/pubsub/vendors/v1/inbound.go` | Decode + Ack/Nack — the analogue of a gRPC handler. Real services replace the log body with an application call |
| gRPC handler | `internal/interface/grpc/handler/vendors/v1/vendor.go` | Command/query dispatch + error mapping; implements `erp.VendorService`'s `CreateVendor` + `GetVendor` |
| Proto contract | `github.com/astronautsid/astro-proto/golang/pb/erp` | The boilerplate uses astro-proto's existing `erp.VendorService` rather than shipping its own proto. Other RPCs declared by that service are inherited from `UnimplementedVendorServiceServer` and return `codes.Unimplemented`. |

**Publish-on-create flow.** `CreateVendorHandler.Execute` constructs an
`event.VendorCreated` from the persisted entity and calls
`NotificationService.SendVendorCreated(ctx, event)` _after_ the transaction
commits. The application layer never touches proto — the per-domain
adapter at `internal/infrastructure/messaging/pubsub/vendors/publisher.go`
converts the domain event to `erppb.Vendor` and `proto.Marshal`s it for the
wire. Publish failures are best-effort — they are swallowed because the
audit log inside the transaction is the durable record; the Pub/Sub event
is a notification, not a contract. The trade-off is at-least-once delivery
on the happy path and at-most-once on publish failure; concrete services
that need stronger guarantees should adopt a transactional outbox.

**Inbound subscription scaffold.** `internal/interface/pubsub/vendors/v1/`
ships an `EventHandler` whose `Handle(ctx, *pubsub.Message)` decodes the
envelope, logs a one-liner, and Acks (Nacks on decode failure). It is wired
in `main.go` Step 10b only when `PUBSUB_VENDOR_EVENTS_SUB_ID` is set, so the
binary boots without GCP credentials. Replace the log body with a real
application call when adopting the pattern in a concrete service.

**The unexported `*_service` trick.** `golibspubsub.New` returns an
unexported type (`*_service`). To inject it across packages, the publisher
and subscriber adapters declare tiny local interfaces (`pubsubService`,
`subscriberService`) matching only the methods they use. The composition
root holds the constructor result via type inference; Go's structural typing
wires the concrete value through without anyone having to name it.

**Handler layout convention.** Handlers are grouped by domain + version: `handler/<domain>/v1/<name>.go`. Use plural (`vendors/`, `orders/`, `users/`) because Go rejects the literal `vendor` directory name (collision with the legacy `vendor/` packages mechanism). The Go package name inside is still `v1`, imported as `vendorv1 "…/handler/vendors/v1"`.

```bash
# 1. Replace the example aggregate (vendor → your domain)
```

## Known limitations

- **Private deps require auth.** `go mod tidy` and `go build` will fail without `GITHUB_TOKEN` configured for `github.com/astronautsid/*`. See the Quick start section.
- **Datadog server-side gRPC interceptor** is left as a TODO in `internal/interface/grpc/server.go`. The client-side interceptor in `grpc_dialer.go` is wired. Add the server contrib when `dd-trace-go/v2` is pinned.
